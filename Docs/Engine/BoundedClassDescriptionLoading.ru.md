# Ограниченная загрузка описаний классов

В `URuntimeLibrary::LoadCompDescriptions` и `UStorage::LoadClassesDescription`
файлы описаний читались через отдельный `std::launch::async` на каждый XML.
Количество запускаемых потоков не ограничивалось. Создание очередного потока
может выбросить `std::system_error` до сбора futures, оставив каталог неполным.

Изменение использует `std::launch::deferred`: чтение и разбор выполняются
вызывающим потоком при прежнем последовательном `future.get()`. Порядок файлов,
сериализация, регистрация описаний и существующая обработка повреждённого XML
не меняются. Новые потоки для загрузки не требуются. Параллельный worker pool
может рассматриваться отдельно после измерения времени запуска.

Это изменение загрузки метаданных. Контракты `Default`, `Build`, `Init`,
`Calculate`, `Reset`, scheduler и возвращаемые ими bool не изменяются.
Образы созданных компонентов не правятся на каждом тике.

Подготовлена интеграционная проверка настоящего `URuntimeLibrary`: точное
сравнение порядка и сериализованного содержимого 32 XML, затем тот же путь
при отсутствии свободных потоков в собственной ограниченной cgroup. Вторая
проверка включается только при kernel-enforced лимите 8–32 tasks; обычный
неограниченный запуск её пропускает. Целевой gate требует обе проверки без
skipped, actual loaded files и закрытие всей группы.

Статус: адресные before/after проверки выполнены на M40 и Elder. На каждом
сервере прежний загрузчик проходит сверку XML и не проходит только проверку
без свободных потоков; исправленный проходит обе без skipped. На M40 также
прошли пять проверок storage/моделей и чистый повтор Classic-6: stderr пуст,
входы, потенциалы четырёх сом и диагностика каналов побитово совпали с прежней
пробой. Проверялся код b3438347fe7dd6d7aeeb49e61236b705e76708b9.

Git-primary корневого репозитория: M40
`374127ae49c361ef35364019b86ea3b67dfb7c51`, Elder
`6117aad55a6d105ad046c1867abc6f4a5a3cb050`. Подробности и независимые квитанции
находятся в Docs/StructTrain/TimeLearner/DescriptionLoadingResourceDiagnostic.ru.md
корневого репозитория. Это адресная приёмка загрузчика, не всего этапа storage.

Точное место исключения в старой пробе Classic-6 не установлено: её журнал
не содержит stack trace. Наличие двух неограниченных launch sites подтверждено
кодом; это не доказательство того, какой из них породил конкретную запись.
