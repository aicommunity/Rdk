# Целые параметры при XML загрузке и копировании

Статус20.11: Windows A3 SDK принят; native81 завершён80 PASS/1 FAIL.
Полная ширина и Copy реального нейрона прошли. LegacyDecimalPrefixes выявил
отдельный дефект кэша текста. Исправление кэша подготовлено в feature-ветке;
новый полный native86 и Linux-приёмка ещё не выполнены.

`USimpleFromStorage` используется штатными операторами `USerStorageXML`,
загрузкой свойств и `UComponent::CopyProperties`. Прежний вызов `atoi`
сначала преобразовывал любой целый параметр в32-битный `int`, а уже затем
приводил его к фактическому типу свойства. Поэтому корректно записанный
параметр мог измениться при Copy или Load. На Windows воспроизведено
`4294967295 → 2147483647`; это значение встречается в
`UContainer::DebugSysEventsMask`, установленном Default в `0xFFFFFFFF`.

Чтение знаковых целых теперь использует `strtoll`, беззнаковых — `strtoull`,
после чего применяется приведение к типу назначения. Это сохраняет точные
значения допустимого диапазона стандартных поддерживаемых целых типов,
включая signed/unsigned64 и unsigned32. Формат записи и XML Type не меняются.

Совместимость парсинга сохраняется для ведущих пробелов, знака и числового
десятичного префикса перед текстом. Беззнаковое `-1` по-прежнему задаёт все
биты. Это исправление ширины, а не новая строгая схема конфигурации:
некорректные и выходящие за диапазон значения не получают новой гарантии.
Их проверяет потребитель конфигурации. Вещественные значения и остальные
типы используют прежние пути чтения.

Три перегрузки прямого `ReadUnsigned` также читают через `strtoull`:
именованный, именованный с индексом и позиционный доступ должны сохранять
весь unsigned32, как общий оператор чтения свойства.

Контракты Build/Calculate/Reset, scheduler и Copy динамического состояния
не меняются. Из сравнения class images не исключаются диагностические
параметры: копия должна сохранять их, даже если они не входят в научный
fingerprint физической модели.

Регрессии находятся в корневом интеграционном target
`Test_PulseLib_StorageComponents`, suite `RdkIntegralXml`. Они используют
реальные XML Save/Load, Environment/storage и `NPulseNeuron`, проверяя
граничные значения, совместимые числовые префиксы, Copy и RegisterClassImage.
Тесты не копируют тело функции десериализации. Windows native78 с исходным
отрицательным результатом59/78 сохраняется; новый полный прогон включает
все исходные78 cases и три дополнительные регрессии.

## Когерентность кэша USerStorageXML

В исходном native81 повторные `SetNodeText`/чтения одного текущего узла
сохраняли первое значение17 вместо−23, unsigned−1 и0. Это подтверждённый
runtime-дефект владельца сериализации, а не повод создавать новый XML fixture
на каждое чтение. Исходный отрицательный результат80/81 сохраняется.

Единый `InvalidateNodeCache` сбрасывает текст, имя, карту атрибутов и их
ссылки до мутации/перехода. Он вызывается из Create, Destroy, Load,
LoadToNode/LoadFieldsToNode, навигации, добавления/удаления/переименования
узла, записи текста и изменения атрибутов. После временного обхода source
в LoadFieldsToNode сбрасывается и кэш восстановленного source-курсора.
Кэш относится к текущему курсору; совпадающее имя не идентифицирует узел.
Наличие атрибута определяется реальным XML, а не частичной картой чтений.
Кэш разбиения строки пути не содержит данных XML и остаётся независимым.

Добавлены четыре production API cases `RdkXmlStorage`: мутации после чтений,
Create/Load/Destroy, переходы между одноимёнными узлами и глубокое копирование
полей с сохранением source-курсора. Пятая новая регрессия `RdkIntegralXml`
проверяет три прямых `ReadUnsigned` и missing-default. Новый cohort содержит
все прежние81 case и эти пять, всего86, без исключений. До его завершения
исправление считается подготовленным, а не runtime-принятым. Не добавляется
обещание checkpoint динамики компонентов или нового контракта копирования
самого объекта USerStorageXML.
