# MDMatrix: изменение формы в существующей памяти

Подтверждённый дефект исходного `027f7f8353608f83b55f3857a2f6c39138df4c65`:
Resize(3,1) после матрицы1×2 может сохранить существующее выделение capacity=3.
В ветви уменьшения числа столбцов старый цикл переносил rows новых строк,
хотя исходно существовала только одна. Он читал Data[2], затем Data[4];
последнее находится за пределами выделенных трёх элементов double.
Последующее заполнение новых строк могло скрывать ошибку в обычной сборке.

Ошибка обнаружена ASan при восстановлении output-state TimeLearner через
MDMatrix::Assign и независимо воспроизведена прямым тестом production MDMatrix,
без копирования тела функции. Root fixture source:
`fc3f10691820f392c17d524fcf0f5f0e4e62fb3b`,
Tests/Unit/Math/Test_MDMatrixResize.cpp. Normal проходит10/10, а ASan исходного
кода аварийно останавливается на минимальном1×2→3×1 до завершения корпуса.
Это не основание считать обычный зелёный тест проверкой безопасности памяти.

Исправление переносит только min(oldRows,newRows) существовавших строк.
Новые строки получают defvalue. Перенос при расширении столбцов остаётся
обратным, но использует индексы, не образуя указатели перед началом Data
при пустом пересечении и после последней скопированной строки.

Сохраняются текущие контракты: прямоугольное пересечение удерживается;
новые клетки инициализируются; равная форма и отрицательные запросы являются
no-op; нулевая размерность меняет логическую форму, сохраняя доступную capacity.
Скалярный Assign после Resize заполняет все клетки. Резервирование capacity
и стратегия аллокации не менялись. Типы контроля: double, int, unsigned char,
bool;242 перехода формы на тип (11×11, fresh/reserved), включая пустые формы.

Проверки исправленной версии и повторный native TimeLearner normal/ASan gate
выполняются отдельно. Здесь не заявляются устранение всех рисков MDMatrix,
поддержка произвольных нетривиальных T или проверка больших размерностей
и переполнения арифметики размеров. Математическая задача обучения не меняется.
