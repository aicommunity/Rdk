# Сравнение штатной XML-сериализации между компиляторами

`USerStorageXML::SamePortableSerialization` сравнивает полные деревья,
не меняя XML, текущие узлы и кэши обоих объектов. Порядок атрибутов
не влияет на равенство. Имена узлов и атрибутов, значения, порядок
дочерних элементов и текста, комментарии и прочие clear-поля сохраняются
в сравнении.

Только значения атрибутов `Type`, `elemType`, `elemVecType` допускают
разные известные написания одного номинального скалярного типа GCC/MSVC.
Например, `d` и `double` описывают один тип; `double` и `int` — разные.
`int`, `long` и `long long` также различаются. Неизвестные строки, включая
имена пользовательских типов, равны лишь точно таким же строкам.
Текстовое содержимое и значения прочих атрибутов не нормализуются.

Метод предназначен для сравнения представлений. Проверки исходных
контрольных сумм, допустимости компонента, диапазона значений, размерностей,
реального класса и связей выполняет владелец документа и штатный загрузчик.
Одинаковый номинальный тип не гарантирует одинакового размера ABI:
например, перенос целого значения проверяется фактическим типизированным
чтением на принимающей платформе.

Штатная запись XML, её имена типов и контрольные суммы не изменяются.
Метод не вызывает Default/Build/Init/Reset/Calculate и не создаёт
обходной способ настройки компонентов или storage-образов.

В корневых интеграционных проверках `PortableNativeXml` предусмотрены
реальная запись скаляра, оба направления сравнения, сохранность XML
и позиции, известные скалярные типы, отрицательные случаи для типа,
значения, размерности, класса, связи, атрибутов и смешанного содержимого.
При добавлении API выполнение этих проверок на серверах ещё не принято.
